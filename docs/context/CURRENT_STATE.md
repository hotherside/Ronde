## Stage

Ronde remains pre-release and is now exclusively a universal iPhone/iPad product. It centres on a searchable Sessions library with Recording Studio for long manual sources and Shot Studio for playback, frame stepping, trim, trace and social export. The Apple Watch shot counter and its round/workout features have been retired. The active automatic overlay uses only accepted source-timed observed samples; predicted flight, landing and numerical carry are absent from the studio. Manual annotations remain separate and labelled.

The prior signed-iPhone TestFlight check produced only one automatic trace across five owner-selected videos, and that line was visually inaccurate. This remains unresolved accuracy evidence. The new source-cadence, track-lineage, loss/reacquisition and apex repairs address reproducible component failures; they do not validate the model on representative golf footage. The current Recording Studio remains a manual source-review workflow and makes no new tracer-accuracy claim.

## Capability status

**Implemented direction, 19 September:** after reviewing the [local HTML concepts](../design/2026-09-19-shot-media/README.md), the owner selected Clubhouse as the foundation, with Cutroom's editing vocabulary and native Liquid Glass controls. The local native slice implements Sessions → Recordings → Bookmarks → source-linked Shots, with favourites identifying Keepers. Manual recordings accept up to 20 minutes from Photos, Files or the native camera. Each bookmark defaults to ±5 seconds, can be adjusted in 5-second increments from 0 to 60 seconds per side, clamps to the source and can be batch-extracted once while preserving existing Shot edits. [ADR 0013](decisions/0013-clubhouse-and-bookmarked-recording-studio.md) remains the historical design selection; [ADR 0014](decisions/0014-native-recording-studio-and-source-linked-shots.md) records the implemented local contract.

Recording Studio plays the full source and generates a sparse thumbnail strip, capped at 12 frames. A derived Shot's frame index and thumbnails are restricted to its source clip plus five seconds on either side, retaining absolute source timestamps. Automatic moment suggestions remain deferred; derived Shots start untraced and support the same explicit Trace shot and correction actions as short imports. Manual recording review does not require a ball track.

## Verification

### Clip-first flow and phone-crash response, 19 September

The owner reported the installed point-selection tracer stuck at 10% followed by an app crash. That progress value occurs after model loading and before the first canonical inference completes. No synced crash/jetsam report was available, and USB/CoreDevice could not reach the phone during investigation. Memory pressure is unconfirmed. The runtime now releases the full RGB cache before inference, checks cancellation around every model load/prediction and uses CPU/Neural Engine on physical iOS. A real-phone repeat is required before describing this crash as resolved.

The accepted flow now opens imported clips shorter than 20 seconds directly in Shot Studio without bookmarks or an analysis wait. Longer recordings use **Choose shots**, with a saved session-wide window inherited by new recordings/bookmarks and existing individual cuts preserved. One **Trace shot** action searches the selected clip for an accepted ball observation, then propagates with EdgeTAM. Ball selection and drawn/adjustable paths are secondary corrections. Detected/person-selected seeds and manual geometry retain distinct provenance. Selected tracking clips may be up to 20 seconds. See [ADR 0018](decisions/0018-clip-first-tracing-and-correction.md); this supersedes the earlier ten-second, point-selection-first interaction below.

The updated app/domain/media suite passes 141 checks with two skips and zero failures on iPhone 17/iOS 27 Simulator (`ronde-feedback-units-v3.xcresult`). This covers import boundaries, archive compatibility, grouped bookmark defaults/inheritance, automatic seed policy, hidden-trace restoration and drawn-path sanitisation/rendering. UI and signed-build verification are in progress. The earlier assisted Mac scores below do not prove new automatic-seed accuracy, iPhone runtime stability or performance. Work is local on `codex/tracer-evidence-benchmark` from `7a6bd012`; no distribution is implied.

### Authentication service recovery, 19 September

The owner's signed-device Apple sign-in failed with `NSURLErrorDomain -1003` while the configured Supabase hostname returned `NXDOMAIN`. The live Ronde project was `INACTIVE`. Resuming that existing project restored `ACTIVE_HEALTHY`; `/auth/v1/health` and `/auth/v1/settings` both returned HTTP 200 with the app's current publishable key, and Apple remained enabled. No app authentication code, keys, provider settings or schema were changed. This confirms backend recovery, not a completed Apple login on the phone; the owner has been asked to retry. ### Local tracer benchmark, 19 September

The uncommitted `codex/tracer-evidence-benchmark` work starts from `7a6bd012484419faf3f23011cee7f4ae12b4a6b3`. It adds source-timed diagnostics/comparisons and, following explicit owner authorisation, an optional selected-point tracking action inside Ronde. Default WASB automatic acquisition, its strongest-peak decoder and eligibility policy are retained. The scope is tracer integration, not redesign. See [ADR 0015](decisions/0015-source-timed-tracer-benchmark.md), [ADR 0017](decisions/0017-opt-in-on-device-ball-tracking.md) and the [validation ledger](TRACER_VALIDATION.md#19-september-source-timed-development-benchmark).

Two owner clips have 113 daylight and 103 night visible-frame reference positions reviewed by agents; independent human verification and uncertain portions remain open. With supplied impact timing, the default tracker localises 87/113 and 80/103 within 12 source pixels, including one daylight and four night wrong-object selections. EdgeTAM with one clear-air point, a supplied interval, model-driven moving 512-pixel crops and a bounded 0.20-second dropout rule reaches 104/113 daylight and 102/103 night within 12 pixels (103/113 and 95/103 within 4 pixels). Nine daylight positions remain missing; night retains a 48.49-pixel launch-streak error and an additional output on an uncertain frame, with none on eight explicitly absent frames. These are assisted results on known development clips, not held-out or physical-phone accuracy.

Full native Swift adaptive parity subsequently passed on the Mac: all 130 daylight callback masks are binary-identical; 117/118 night masks are identical and the remaining mask differs by one pixel (minimum IoU 0.99875, maximum centre difference 0.0234646 pixels). Actual PTS, empty decisions, crop resets and termination agree. The result contains 120/110 canonical frames, with 104 nonempty observations per clip; tracking takes 41.737/34.936 seconds on the Mac. The earlier interrupted 18-callback run and incorrect PNG-byte IoU report remain retained as superseded evidence. The corrected source decoder matches all 432 PTS and 277 cached RGB frames; the direct-original-video provider separately passes 18 RGB and eight tensor comparisons with exact timing/index mapping and one retained RGB frame. This cache bound is not total model/process memory. Both supplied sources have identity transforms; nonidentity rotation remains a separate check.

The app now includes the same eight native runtime files through `project.yml`, plus `EdgeTAMTrackingService`, its adapter and persisted `SeededModelTrace`. Shot Studio offers source-frame selection/zoom, cancellation and separate segmented preview/export. Models are verified and loaded per operation; account/source ownership is checked before saving. Main-project builds require the externally prepared, ignored `.local-models` resources. An opt-in test specification adds private fixtures only to the XCTest bundle. The first integration build failed resource packaging; the five compiled model trees, constants and licence are now prepared and hash-verified, and XcodeGen succeeds.
